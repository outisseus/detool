# Pieverse research note

Pieverse is useful evidence that agent infrastructure needs identity,
authorization, accounting, auditability, and reputation around external
actions. Its public positioning is explicitly Web3-native and emphasizes
agent-to-agent payments and on-chain infrastructure.

DeTool takes the transferable architectural lesson, not the implementation
commitment:

- the first-class object is a verifiable external state transition;
- providers need scoped performance history and dispute semantics;
- payment and settlement are optional adapters, not the system identity;
- MCP is one transport among many, not the product boundary;
- blockchain and tokens remain optional until the local execution and
  verification loop works without them.
